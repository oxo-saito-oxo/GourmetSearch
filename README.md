# ぴんとごはん

現在地の近くにあるお店を、写真を見ながら直感的に選べるレストラン検索アプリです。
ホットペッパー グルメサーチAPIを使用しています。

---

## アプリ名

ぴんとごはん

地図の「ピン」（近くのお店を探す）と、写真を見て「ピンとくる」（直感的に選ぶ）の2つの意味を込めました。

## ビルド方法

APIキーはリポジトリに含めていません。ビルドする前に、次の手順でご自身のAPIキーを設定してください。

1. `Config/Secrets.sample.xcconfig` をコピーし、同じフォルダに `Secrets.xcconfig` という名前で保存する
2. `Secrets.xcconfig` の `YOUR_API_KEY` を、[リクルートWEBサービス](https://webservice.recruit.co.jp/) で取得したAPIキーに書き換える
3. `GourmetSearch.xcodeproj` を Xcode で開き、実行する

`Secrets.xcconfig` は `.gitignore` に入れているため、Gitには含まれません。

## 機能概要（機能一覧）

### 検索条件
- 現在地を取得して検索（検索ボタンを押した時点の位置を使用）
- 検索半径：300m / 500m / 1km / 2km / 3km（目盛りに止まるスライダー）
- ジャンル：すべて、居酒屋、和食、洋食、中華、焼肉・ホルモン、ラーメン、カフェ・スイーツ
- こだわり条件（複数選択）：個室あり・飲み放題・食べ放題・深夜営業・駐車場あり

### 検索結果
- カード型の一覧（写真・現在地からの距離・ジャンル・予算・店名・アクセス）
- 条件に合うお店の総件数を表示
- ページング（一番下までスクロールすると、次の20件を自動で読み込む）
- 0件のとき：距離を1段階広げて探し直すボタン（3kmのときは表示しない）
- 位置情報が許可されていないとき：設定アプリを開くボタン
- 通信エラーのとき：再試行ボタン

### 店舗詳細
- 写真・店名・ジャンル・予算・現在地からの距離
- 住所・アクセス・営業時間・定休日（長押しでコピー可能）
- 経路を見る（マップアプリで現在地からの徒歩の経路を表示）
- 予約・電話（ホットペッパーのお店のページをSafariで開く）
- 共有（お店の名前とページのURLを、LINEなどで送る）
- 設備・サービス（個室・飲み放題・食べ放題・深夜営業・駐車場）の有無

## 画面概要

| 画面 | 内容 |
|---|---|
| 検索条件画面 | 距離・ジャンル・こだわり条件を選び、「この周辺で探す」で検索する |
| 検索結果画面 | 写真付きのカードでお店を一覧表示する。読み込み中・0件・位置情報の拒否・通信エラーのときは、それぞれの案内を表示する |
| 店舗詳細画面 | お店の詳しい情報と、経路・予約/電話・共有のボタンを表示する |

## 利用技術（フレームワークやAIなど）の選定理由

- **UIKitは使用していません**（画面はすべてSwiftUIで作成）
- **SwiftUI**：課題でSwiftUIの使用が指定されていたため。画面の状態（読み込み中・0件・エラーなど）に合わせて表示を切り替える書き方がしやすい
- **iOS 17 以上**：`@Observable`・`ContentUnavailableView`（0件やエラーの画面）・`sensoryFeedback`（スライダーの振動）など、コードを短く素直に書ける機能が使えるため
- **外部ライブラリを使わない**：今回の機能は標準のフレームワークだけで実現できたため。ライブラリの更新や互換性を気にしなくてよい
- **MVVM**：画面（View）と、データの取得や状態の管理（ViewModel）を分けて、それぞれの役割をはっきりさせるため
- **プロトコル（`ShopSearching`）で通信部分を差し替え可能に**：プレビューやテストで、本物の通信の代わりにダミーを使えるようにするため
- **async/await**：通信や現在地の取得を、上から順に読める形で書けるため

### 生成AIの利用について

生成AI（Claude）を、**ペアプログラミングの先生**のような役割で使いました。

- 開発の進め方の相談、コードの下書き、エラーの原因調査、デザイン案とアイコン案の作成に利用しました
- コードは小さな単位で受け取り、1ステップずつ動かして確認しながら進めました。分からない書き方（`private(set)`、`protocol`、`continuation` など）はその都度質問し、AIからのクイズに答えて理解を確かめてから次に進みました
- アプリ名・配色・デザインの方向性（カード型の一覧、距離のスライダー、こだわり条件の追加、お気に入りを入れずに共有ボタンを残す判断など）は、自分で決めました

## コンセプト

**仕事帰りや旅行先で、条件に合うお店を手軽に見つけたい人のためのアプリ**です。

知らない場所や疲れているときのお店探しは、細かい情報を読み比べるより、「近い」「写真がおいしそう」で直感的に決めたいことが多いと考えました。そこで、距離で範囲を決めて、写真の大きなカードで候補を選ぶ形にしました。この体験は、マッチングアプリの「距離を設定して、写真のカードで選ぶ」UIに近いと考え、参考にしています。

アプリ全体は、はちみつ色とこげ茶を使った温かい雰囲気にして、「ほっとできるごはん」を探すアプリらしさを出しました。

## こだわったポイント

**実際に使ってみて見つけた課題を、機能に反映したこと**です。

帰省先（新潟県）で実機を使って試したところ、300m・500mでは1件もヒットせず、1km以上でようやくお店が見つかりました。旅行先のように土地勘のない場所で使うと、狭い範囲では0件になりやすいと分かったので、0件のときは「距離を1段階広げて探す」ボタンで、すぐ探し直せるようにしました。3kmのときはそれ以上広げられないので、このボタンは出さずに「条件を変える」だけを表示しています。

ほかにも、次の点にこだわりました。

- **うまくいかないときの案内を分けた**：0件・位置情報の拒否・通信エラーで、それぞれに合った案内とボタン（距離を広げる・設定を開く・もう一度試す）を出しています
- **検索できる条件と、詳細で見られる情報をそろえた**：検索画面の「こだわり条件」と、詳細画面の「設備・サービス」を同じ5項目にしました
- **詳細画面ではAPIを呼び直さない**：一覧ですでに持っているデータをそのまま使うので、タップしてすぐに表示され、通信の失敗もありません
- **電話番号がAPIにないことへの対応**：「予約・電話」ボタンでホットペッパーのお店のページを開き、そこから予約や電話ができるようにしました
- **APIキーをリポジトリに含めない**：xcconfig と `.gitignore` を使い、キーを公開せずにビルドできるようにしました

## デザイン面でこだわったポイント

- **温かい配色**：はちみつ色 `#EAA221` とこげ茶 `#654321` を中心に、焼き菓子やコーヒーのような温かい雰囲気にしました。この世界観を守るため、ライトモードに固定しています
- **文字の読みやすさ**：背景と文字のコントラスト比を計算し、オレンジの上には文字を置かず、スライダーやアイコンなどのアクセントだけに使いました
- **写真が主役の一覧**：カードの写真を大きめにし、写真の上に「現在地からの距離」のバッジを重ねて、写真と距離で直感的に選べるようにしました
- **距離のスライダー**：APIで指定できる5段階に合わせて、目盛りに止まるスライダーにしました。自由に動かせると指定できない値が出てしまうためです。目盛りが変わるたびに軽く振動します
- **詰め込みすぎない詳細画面**：店名を先に置き、ジャンル・予算・距離を1行にまとめました。設備は横1列に並べて、場所を取りすぎないようにしました
- **アイコン**：「ピン」と「ごはん」を1つの形（目玉焼きの形をした地図のピン）にまとめました。ホーム画面で小さく表示されても分かるよう、細かい部分を入れていません
- **使いやすさ**：タップできる部分は44ポイント以上にしました。VoiceOverで「選択中」や設備の「あり・なし」が伝わるようにしています

## 既知の不具合・制限

- APIで取得できる写真が最大238pxのため、詳細画面の上部の写真が少しぼやける
- 現在地からの距離は直線距離で、実際に歩く距離とは異なる
- APIのお店の座標が建物単位で登録されていることがあり、同じ建物の中のお店は同じ距離（現在地と同じ建物なら「0m」）と表示される
- 2ページ目以降の読み込みに失敗したときは、表示中の一覧は消さずにそのままにしている（もう一度下までスクロールすると再試行する）。失敗したことはユーザーに表示していない

## 自己評価

課題の必須機能（現在地の取得・検索半径の指定・一覧・ページング・詳細）はすべて実装でき、0件やエラーのときの体験まで作り込むことができました。

一番うれしかったのは、自分のiPhoneで、本物の現在地を使ってアプリが動いたときです。実際に帰省先で使ってみたことで、地方では狭い範囲だと0件になりやすいという、シミュレータだけでは気づけなかった課題を見つけ、改善につなげられました。

苦労したのは、APIまわりの実装とエラーへの対応です。APIキーの登録やキーを公開しない設定のほか、ビルドエラーや画面が思ったとおりに動かない場面が何度もありました。その中で、エラーメッセージを読んで原因を絞り込む力が身についたことが、この課題で一番の学びです。

一方で、テストを書けなかったことや、お気に入りなどの機能まで手が回らなかったことは反省点です。次は、ViewModelのテストを書きながら開発することに挑戦したいです。
